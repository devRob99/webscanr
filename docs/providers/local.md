# Local passive checks

**Status:** 🟡 all checks built and tested on fixtures; live mode untested

## What it adds
Checks WebScan performs itself, from this machine, with the same requests an ordinary visitor's browser
or a mail server would make:

| Check | Looks at |
|---|---|
| `headers` | CSP, HSTS, X-Frame-Options / `frame-ancestors`, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, version-leaking `Server` / `X-Powered-By` |
| `tls` | Certificate validity, days to expiry, TLS 1.0/1.1 acceptance, HTTP→HTTPS redirect |
| `cookies` | `Secure`, `HttpOnly`, `SameSite` (names only, never values) |
| `email` | SPF, DMARC, common DKIM selectors for the asset's `email_domain` |
| `donation` | HTTPS on the page and form action, payment processor, third-party scripts (pages in `donation_paths`) |
| `privacy` | Third-party trackers, privacy policy link |
| `exposed_files` | A few single GET requests (`/.git/HEAD`, `/.env`, common backups) compared with a baseline 404 |

## What data it sends externally
Nothing to any third party. Requests go to the approved target itself, and DNS questions go to the
machine's configured resolver.

## Environment and config
- No keys. Live mode needs `--live`, `WEBSCAN_LIVE_MODE=true`, and `"local"` in `enabled_providers`.
- `config/providers.json` → `local`: `checks`, `request_delay_seconds`, `timeout_seconds`,
  `cert_expiry_warning_days`, `dkim_selectors`, `exposed_paths`.
- Per asset in `assets_metadata.json`: `donation_paths`, `email_domain`, `platform`.

## Safety properties
- Each request's host is authorized by the scope enforcer; redirects are not followed automatically.
- Requests are paced (`request_delay_seconds`); response bodies are capped at 500 KB.
- Contents of exposed files are checked for a signature and then discarded.
- Internal assets may be checked (this is an approved local tool), but only in live mode.

## Demo mode
Uses recorded fixtures in `data/mock/local/`, generated by `scripts/build_local_fixtures.py`.

## Steps to finish wiring it
1. With written authorization, run `webscan scan --asset <alias> --live` against one low-risk public site.
2. Compare results with a manual check (browser developer tools, an online header checker).
3. The TLS 1.0/1.1 probe depends on the local OpenSSL build; if it is inconclusive, nothing is reported.
4. Extend `PAYMENT_PROCESSORS` and `TRACKERS` in `checks.py` as needed.
